TTS 与 ASR 看似只是输入输出反过来，但难度结构完全不同。 ASR 类似分类任务；TTS类似生成任务。

困难 01

评估难

没有 WER 这种客观指标，只能用 MOS（Mean Opinion Score）让人打分。

主观 · 昂贵 · 跨论文不可比
困难 02

训练目标含糊

直接对 mel 谱做 L2 回归，模型会输出「所有可能读法的平均」——过平滑，听起来含混发闷。

over-smoothing · 后来靠生成式建模解决
困难 03

可控性要求高

业务上要指定说话人、情感、语速、停顿，这要求模型把「内容」与「风格」解耦。

disentanglement · zero-shot 克隆的前提

手工时代：三条路，各让一步

共振峰、拼接、HMM 三种方案在音质 / 灵活度 / 体积上各占一角，谁都补不齐另两角。 真正的共同局限不在音质，而在整条流水线全靠手工设计。

2016 — 2021 · neural 05 / 22

神经网络吃掉声学建模：五年里少了四个手工模块

这一代的每一步都在解决上一步留下的代价：Tacotron + WaveNet 打通了两段式但都慢、attention 还会崩 → FastSpeech 并行提速但要外部对齐 → VITS 干脆把两段缝成一个模型。

2016.09 → 2017.03MOS ~4.5

Tacotron + WaveNet

Google / DeepMind
两段式神经流水线

两者是互补的两半，不是竞争关系：Tacotron 用 attention seq2seq 做「文本 → mel 谱」，WaveNet 用因果空洞卷积做「mel 谱 → 高质量波形」。合起来第一次让整条 pipeline 端到端可训。

WaveNet 逐采样点自回归极慢（16 kHz = 每秒 16000 次预测）；Tacotron 的 attention 会崩——跳帧、漏字、重复。

WaveNet：因果空洞卷积Mel 谱 → 波形
2019 — 20MOS ~4.4

FastSpeech + HiFi-GAN

Microsoft / Kakao · 并行化 + GAN

用显式 duration predictor 替代 attention：预测每个音素占多少帧，再展开成整段 mel 并行生成。

duration 标签靠外部对齐（教师模型或 MFA）。

Duration Predictor + 长度调节器Length Regulator

每个音素预测出固定帧数，长度调节器直接展开成整段 mel——一次前向并行产出全部帧，不必等前一帧算完。270× 加速仅指 mel 生成，端到端含声码器约 38×。

KAIST · 一体化
Flow + MAS + GAN 解码器

彻底统一：取消 mel 中间表示，文本直接产出波形。

单阶段训练、单模型部署，但以单说话人为主——零样本克隆还要等下一代。

生成式大模型重定义问题：音频成了一种 token

VALL-E 做的不是提升音质，而是换了问题的提法——把 TTS 变成「codec token 上的语言建模」。 这一步让 TTS 接上 NLP 主线，白拿整个 LLM 时代的工程红利。

2023.01MOS ~4.3

VALL-E

Microsoft · codec token LM
60k 小时 LibriLight

用 Encodec 把音频离散成 token，再训 GPT 式自回归 Transformer：输入「3 秒参考音频 codec + 目标文本音素」，输出目标音频 codec token。

token 逐个解码慢；仍需音素作为条件。

音频 = token 序列codec lm
2024.06 — 10MOS ~4.4

E2-TTS
F5-TTS

上海交大 SWivid / MS
Flow Matching + DiT

针对 codec LM 的两个软肋：AR 慢、依赖外部对齐。E2 把训练变成音频填空——挖洞补全，文本只是另一个条件，于是彻底不要音素对齐、时长预测和 G2P 字典。

训练数据需求大。

直线路径 + 音频填空flow matching
音频填空任务（infilling）

学的是连续时间下的速度场 v(x,t)，用 ODE 求解器替代 diffusion 的 SDE——步数从千级压到十几步。

Codec可以抽象理解为音频的压缩 + 还原：用更少的数据表示同一段音频，再还原回来。中间的压缩表示是重点。

03 Codec 编/解码器 ②
RVQ-VAE 10 / 22

无监督 codec 共用同一个数学骨架

主流无监督 codec 都是基于 RVQ-VAE，关键参数是码本数量K、码本大小V，帧率f。

codec 参数对 LLM 推理的影响

codec LM 架构里，AR 只负责第 1 层，剩下 K−1 层由 NAR 并行/迭代补齐——基本不占自回归步数。 真正决定 LLM 要跑多少步的，只有帧率 f。

码本大小 V 影响很小
码本数量 K 影响中等
帧率 f 影响较大
codec 的信息容量上限：bitrate 由三个参数共同决定
bitrate = K × log₂V × f

VQ换成 FSQ：解决码本坍塌问题

CosyVoice 1 用普通 VQ（单码本 4096），2 换成了 FSQ。换的理由不是精度，是码本利用率。

VQ 的老毛病：码本坍缩（codebook collapse）

码本是学出来的。训练早期少数码字先被选中，梯度只更新它们，它们变得更容易被选中 —— 正反馈。 最后大量码字从头到尾没被选中过一次，标称 4096，实际有效可能只有几百。你为词表付了钱，但没拿到货。

训练更简单

没有可学码本，commitment loss 也不需要了，跟着一起消失的还有码本学习率这个难调的旋钮。

词表实际可用

代价：表达力受形状约束

为什么这里换得起、Encodec 那边换不起：语义 token 只装内容，一个码本就够，FSQ 那点表达力损失无所谓。 无监督声学 token 要装音色和环境，靠的是 8 层残差堆精度，对每一层的表达力都很敏感。能不能换量化器，取决于你让 token 装多少东西。

flow matching 16 / 22

Flow Matching：不学去噪，直接学速度场

和 Diffusion 目标完全一样 —— 从噪声生成数据。区别只在走什么路径： Diffusion 沿一条曲折的随机路径倒推，Flow Matching 直接连一条直线。直线可以大步走，于是 1000 步变 10–32 步。

Diffusionreverse SDE~1000 步

每步都要注入随机性再去噪（reverse SDE）。路径抖，步子必须小，否则数值积分会崩。

Flow MatchingODE10–32 步

路径完全确定，没有随机性（ODE）。方向恒定，所以能大步跳 —— 这是 SD3 / Sora / F5-TTS 都换 FM 的原因。

训练

learn the velocity field
01
在直线上随机取一点
采一个真实 mel x₁、一份高斯噪声 x₀、一个时刻 t，插值出中间态：
xₜ = (1 − t)·x₀ + t·x₁
02
这一点的「正确速度」是已知的
直线的瞬时方向就是终点减起点，是个常数 —— 不需要任何近似，这是 FM 简洁的根源：
v(xₜ, t) = x₁ − x₀
03
让网络去拟合它
条件（文本 / token / 音色 / 参考 mel）一起喂进去，回归损失：
L = ‖ vθ(xₜ, t, 条件) − (x₁ − x₀) ‖　F5 用 MSE；CosyVoice 2 论文用 L1

推理

integrate along the field
01
从纯噪声出发
按目标长度采一张和 mel 同形状的高斯噪声 x₀。长度必须先定 —— 这正是 F5 不能流式的根因。
02
按速度场往前积分
最简单的 Euler 解法，每步问网络一次「现在该往哪走」：
xt+Δt = xₜ + Δt · vθ(xₜ, t, 条件)
03
走完 NFE 步就得到 mel
NFE 就是质量旋钮：F5-TTS 默认 16、CosyVoice 2 默认 10。降到 8 步会明显塌缩。

03 扩散模型 ②
CFG & sway sampling 17 / 22

两个常见的推理参数

上一页的 ODE 求解时有两处可以调： 一个决定参考音色贴得多紧，一个决定每一步该走多大。

CFGclassifier-free guidance 推理期 · 需训练配合

核心用途：调节生成结果对参考音色的贴合程度。做法是跑两次网络 —— 一次给参考音色条件、一次完全不给 —— 往「参考 − 无参考」的方向外推：

ṽ = vθ(xₜ, t) + β·( vθ(xₜ, t ; Φ) − vθ(xₜ, t) )
vθ(xₜ, t)无参考音色生成 —— 不给任何 speaker / 参考音频条件的预测 vθ(xₜ, t ; Φ)参考音色生成 —— Φ = { speaker emb v, 语义 token μ, 参考 mel X̃₁ }
β = 0退化成无参考音色生成，Φ 完全不起作用
β ↑参考音色的权重被放大，生成结果更贴参考音频，但节奏容易变僵硬
两个前提训练时必须随机丢掉条件，模型才学得会「无参考音色」这一项；推理每步算两遍，NFE=10 实际是 20 次前向

F5-TTS 默认 β=2.0，CosyVoice 2 论文默认 β=0.7，两家参数化写法一致——数字越大，音色引导越强。

Sway Samplingnon-uniform timesteps 纯推理期 · 不用重训

核心用途：把有限的几步 ODE 求解，分配到最需要精度的地方。噪声端（t→0）数据还很粗糙、方向变化剧烈，得小步走才不会一步就偏了；数据端（t→1）已经接近真实分布，粗放地大步走也能收敛：

t′ = t + coef · ( cos(πt/2) − 1 + t ) coef = −1.0（F5 默认）把采样密度推向 t=0；coef = 0 退化成均匀（图中红线）

同样 16 步，Sway 有 11 步落在前半段（均匀只有 8 步）。F5 实测 WER 降约 15%、SECS 提升 0.05，且和训练完全无关，任何模型都能直接套用。

两者可以同时开，互不打架

F5-TTS 默认两个一起用：nfe_step=16, cfg_strength=2.0, sway_sampling_coef=-1.0。 Sway 可以无脑开（不花钱、不用重训）；CFG 得按场景调 β，且会让推理成本翻倍。

03 声码器 ①
vocoder 19 / 22

声码器：把 Mel 谱还原成能听的波形

前面所有模块的输出都是 Mel 谱，但耳朵只能听波形。这一步不是格式转换 —— Mel 谱是有损压缩的结果，反过来走没有唯一答案，只能让神经网络猜一个听起来合理的。

对复数频谱取绝对值，相位就此丢失

FFT 出来的是复数频谱，每个频点既有幅度又有相位。图中「对复数取绝对值」这一步只保留幅度，相位从数学上直接被丢弃——不是压缩，是删除。 于是同一张 Mel 谱，配上不同的相位能还原出无数条不同的波形，波形 → Mel 谱是一条多对一的单行道。 声码器要做的事，就是用一个模型根据 Mel 谱把相位信息补全，才能还原出听起来合理的原始波形。

非流式零样本 (ICL)

non-streaming
[S] + 提示文本 + 待合成文本 + [T] + 参考语音 token
01
参考语音 token 固定放在序列尾部，当成 in-context 的音色/风格样例；LM 只自回归生成待合成部分。
02
实例：提示 7 token + 待合成 14 token + [T] + 参考 75 token = 98 token 输入，逐步生成到 [E]，产出约 87 个语音 token（14 个汉字 ≈ 3.5 秒 × 25 Hz）。

流式零样本 (ICL)

streaming
[S] + 文本块₁ + 语音块₁ + … + 文本块ₖ + 语音块ₖ + [T] + 剩余语音 token

声码器parameters → waveform

把 F0 + 频谱参数还原成波形，是流水线的最后一步，也是「机械音」的主要来源。

例子

F0=220Hz + MGC → STRAIGHT/WORLD 滤波器 → 波形——典型的经典参数化 vocoder 流程。

为什么要手工设计

激励信号建模、最小相位滤波器设计都是经典信号处理算法，参数和假设都靠工程师手工调优，天然带有嗡鸣感。

后来被什么吃掉

WaveNet 到 HiFi-GAN 一代神经 vocoder 用学习到的生成过程取代手工滤波器；再往后，波形还原被整段折进 codec 的解码器里。
