每天点开那个小飞机图标的时候，你大概不会想到，背后是一场持续了三十年的军备竞赛。

这篇文章回答一个问题：VPN 协议到底在解决什么问题，它们又是怎么一代代被逼着进化的。你会看到每一代方案如何解决上一代的痛点，又如何引入新的痛点——像一部剧情环环相扣的连续剧。

全文用一套贯穿始终的比喻，先立好：

  • TCP = 快递公司：保证送到、按序重装、丢了补发
  • TLS = 带锁的箱子：防偷看、防冒充（HTTPS 里的 S 就是它）
  • HTTP = 箱子里的信：你实际想说的内容
  • 防火墙 / DPI（深度包检测） = 海关：不仅看箱子外观，还有 X 光和磅秤

核心论点：三十年只围绕四件事——加密、性能、被动伪装（防 DPI 统计）、主动探测伪装（防扫描）。矛盾的焦点逐代转移：先把锁做结实，再把车做快，最后拼命让箱子长得不像 VPN。每一个"解决"，都精确地成为下一代的"问题"。

一、预备知识：五个必须先懂的概念#

不铺垫这五个概念，后面每一章都会绊倒你。已熟悉的读者可以跳到第二节。

1.1 分层模型：每层只认识相邻的层#

你在浏览器输入 https://github.com，数据从上往下层层包装：

┌─────────────────────────────┐
│  HTTP 请求                    │  ← 信："GET /首页"（说什么）
├─────────────────────────────┤
│  TLS 加密                     │  ← 装进带锁的箱子（防偷看、防冒充）
├─────────────────────────────┤
│  TCP                          │  ← 快递公司：编号、补发、按序重装（保证送到）
├─────────────────────────────┤
│  IP                           │  ← 邮编和路网：逐跳转发（找到路）
└─────────────────────────────┘

接收方反过来一层层拆。关键纪律：每层只认识相邻的层，不关心更里面装的是什么——快递员不拆锁，锁不读信，信不管走哪条路。记住这条纪律，后面所有"伪装"原理都建立在它之上。

1.2 TCP 与 UDP：快递公司 vs 明信片#

互联网底层（IP）是"尽力而为"的——包会丢、会乱序。TCP 在这上面建一条可靠管道：

  • 先建立连接（三次握手）：发货前双方通电话，确认双向都活着
  • 每个包编号，丢件补发、按序重装
  • 淑女式拥塞控制：发现网络堵了主动减速（一丢包速率砍半再慢慢爬）
  • 只认字节，不认含义

它的孪生兄弟 UDP 是寄明信片：写完扔进邮筒就走，不等回执、丢了不补。快、省事、不可靠。DNS 查询、视频通话、游戏、QUIC 都走 UDP。

这条分野贯穿全文：海关能一眼区分"货车（TCP 长连接）“和"明信片流（UDP）"；TCP-in-TCP 会连环追尾；QUIC 与 Hysteria 的整个故事都建立在 UDP 上。

1.3 TLS：带锁的箱子 + 营业执照#

明文的 TCP 管道上，沿途任何路由器都能读到你信里的每个字。TLS 做两件事：

  1. 握手：双方公开协商出只有彼此知道的会话密钥（数学上保证旁听者算不出来），同时用证书验证对方身份——证书就是营业执照，由权威 CA 签发，防止有人冒充 github.com
  2. 加密传输：之后所有字节变成乱码

三个要点：

  • TLS 不是网站专用——它是通用安全层，邮件、聊天、数据库连接都能套，你的代理隧道也靠它。这正是伪装的原理：TLS 箱子外观全一样，海关分不清里面是 HTTP 还是隧道货
  • TLS 站在 TCP 肩上（握手经不起丢包乱序；UDP 上的替代品是 QUIC，第六章讲）
  • 前身叫 SSL，改名两代了，老人还习惯叫 SSL

HTTPS = HTTP over TLS over TCP，名字里的 S 就是 TLS，端口号从 80 换到 443，仅此而已。

1.4 RTT：所有性能讨论的计量单位#

RTT（Round-Trip Time，往返时延）= 一个包从发出到收到回音的完整一圈。北京到美国一圈约 150–250ms，其中大头是物理传播——光跑距离要的时间，协议再好也压缩不掉。

为什么它是命根：握手是"回合制"的，每问一句等一圈。打开一个网页约 3–4 个来回，跨国线上光手续就 800ms。所以后面一切提速技术，本质上只有两条思路：少问几句（砍 RTT 次数），或一次多装点（加大窗口/带宽）。

1.5 用户态与内核态：书房 vs 物业机房#

操作系统把内存划成两个世界：

┌────────────────────────────────┐
│ 用户态（你家书房，隔离、安全）        │
│   浏览器 · Clash · 游戏客户端       │
└──────────────┬─────────────────┘
               │ 系统调用（递申请）
┌──────────────▼─────────────────┐
│ 内核态（小区物业机房，特权）          │
│   TCP/IP 协议栈 · 网卡驱动         │
└────────────────────────────────┘

TCP 在内核态——全系统共享、性能最优，但改 TCP = 改操作系统 = 等全世界升级。这为后面 QUIC 的"用户态革命"埋下伏笔：任何想快速进化的协议，都得搬出机房。

二、正统 VPN 时代：从能用到好用（1999–2020）#

这一章的主角解决的是前两件事：把锁做结实，把车做快。它们的设计目标是"安全地连接远方的内网”——没人想过要躲谁。这个天真，正是它们后来集体阵亡的原因。

2.1 PPTP（1999）：纸箱 + 儿童锁#

技术：GRE 协议做隧道，MPPE（RC4）做加密，MS-CHAPv2 做认证。

引入了什么：第一个"人人可用"的 VPN——Windows 95/98 内置，点几下鼠标连公司内网。

怎么死的：RC4 加密早被密码学界判死刑；2012 年研究员 Moxie Marlinspike 用一台普通电脑暴力破解了 MS-CHAPv2。更糟的是 GRE 协议极其显眼，海关一眼识别。现状：安全界公认"视为已破解"，任何现代系统都不该启用。

2.2 L2TP/IPsec（1999–2000）：装甲集装箱，过关排六趟队#

技术：L2TP 只管装箱不管上锁（自身无加密），必须捆绑 IPsec 提供加密和认证——你说的"L2TP/IPsec"其实是两辆挂在一起的车。

引入了什么：AES 军规加密（锁终于结实了）、证书认证（签字伪造不了了）。解决了 PPTP 的致命问题。

新的问题：双重封装每个包裹白白多背几十字节；IKEv1 握手要来回六七趟，高延迟网络下连接等一两秒；固定走 UDP 500/4500 端口，防火墙按图索骥。

2.3 OpenVPN（2001）：车牌随便换#

技术：基于 SSL/TLS 协商密钥，可跑在 UDP 或 TCP、任意端口上。

引入了什么：开源可审计；车牌随便换（端口任意，还能走 TCP 443 混进 HTTPS 车流——伪装思路的雏形）；跨平台 + NAT 穿透。

新的问题：数据在内核和用户态之间来回搬运，性能有天花板；十几万行代码，攻击面大，配置项多到能出一本书。

2.4 IKEv2/IPsec（2005）：常旅客通道#

技术：把繁琐的 IKEv1 推倒重写成 IKEv2，握手从六七趟砍到四趟；加上 MOBIKE 扩展。

引入了什么：MOBIKE 漫游（手机从 WiFi 切 4G，IP 变了连接自动跟着走，不断线）+ 内核态实现（性能直逼硬件极限）。以前的协议每次换网络都要重新排队过海关，IKEv2 给你办了张常旅客卡。这也是它至今仍是 iOS/Android/Windows 原生内置、移动端体验最好的原因。

遗留问题：UDP 固定端口特征明显；配置复杂度堪比报税。

2.5 SSTP（2007）：伪装成 HTTPS 的代价#

技术：把 VPN 流量整个塞进一条 TLS 通道，走 TCP 443。

引入了什么：完全的端口伪装——443 是互联网命脉，海关不可能封整个 443，否则银行购物搜索全灭。

新的问题——TCP-over-TCP 雪崩：隧道本身是 TCP，里面的流量往往也是 TCP。丢一个包，里外两层都重传、都降速，互相以为对方堵了，恶性循环。形象地说：里层司机看到堵车踩刹车，外层司机看到里层刹车以为更堵，跟着踩，最后一起趴窝。

2.6 WireGuard（2015/2020）：4000 个零件的超跑#

技术：约 4000 行代码（OpenVPN 十几万、IPsec 几十万），密码学套件固定且现代（Curve25519 + ChaCha20-Poly1305 + BLAKE2s），内核态运行。

引入了什么：

  • 极简 = 安全：一个下午能审计完；套件固定，杜绝降级攻击
  • 1-RTT 握手：一个来回就出发
  • 内核态 + 无连接设计：吞吐拉满，切网无缝续接
  • 静默模式：不认识的人敲门，直接装聋——端口扫描器看到一堵墙
  • 配置极简：十几行搞定，IPsec 用户看了会哭

遗留问题：纯 UDP 无得选；跑得再快，长流 UDP 的形态依然显眼——海关撬不开箱子，但能看出"这车天天定时跑同一条不寻常的线路"。

正统 VPN 小结：这一时代解决了"锁结实"和"车够快"，但所有协议都有一个共同点——箱子外观一眼就是 VPN。2012 年前后，防火墙对 IPsec/OpenVPN 的握手特征已能精准识别，正统 VPN 在对抗场景下集体阵亡。矛盾焦点随即转移：长得不像 VPN，比什么都重要。

三、Shadowsocks 与 SSR：第一个专为翻墙而生的协议（2012）#

3.1 历史性的转变：设计目标换了#

Shadowsocks 诞生的意义，不在某个具体技术，而在一次目标切换：此前所有 VPN 协议（PPTP 到 IKEv2）的设计目标是"安全地连接远方内网"，从没想过要躲谁；SS 是第一个以对抗海关为核心设计目标的代理协议。作者 clowwindy 在 2012 年用 Python 写出第一版，从此"VPN"这个词的重心，从虚拟专用网滑向了翻墙工具。

3.2 技术：一个没有任何标签的黑箱#

架构极简：本地跑一个 SOCKS5 代理，流量用预共享密码加密后发给服务器中转。关键设计：

  • 无握手：没有协议协商过程，第一个包就是数据
  • 无特征字符串：不出现任何可搜索的协议标识
  • 加密演进：早期用流密码（后来证明弱），社区版随后统一到 AEAD（chacha20-ietf-poly1305 / aes-256-gcm）

形象地说：SS 发出的流量是一个没有任何标签的纯黑箱子——X 光照进去也是一片雪花噪声。相比之下，OpenVPN 的握手像在海关面前报户口。

3.3 死穴与 SSR 的加戏#

海关的反击分两手：

  • 被动统计：“看不懂"本身就是嫌疑——一个路口每天有几百个纯黑无标签的箱子经过，迟早立规矩：黑箱子一律扣
  • 主动探测：向可疑服务器直接发 SS 协议包，看响应方式是否符合协议特征——符合就标记

2015 年，clowwindy 被约谈，项目从 GitHub 删除。社区随即分裂出 ShadowsocksR（SSR），核心卖点是两个插件：

  • 混淆插件（obfs）：在密文外再套一层伪装头，让流量看起来像普通 HTTP/TLS
  • 协议插件（protocol）：改写认证流程，防主动探测、防重放

但 SSR 的路子有个内在悖论：加戏越多，特征越多——自创的混淆格式本身就是一种新指纹，海关收集样本后照样能训练出分类器。SSR 也因作者停更而衰落。

SS 正统生态后来走了条更聪明的路：SIP003 插件体系（simple-obfs，以及后来的 v2ray-plugin——把 SS 流量整个包进 WebSocket + TLS）。这等于承认了一件事：光靠黑箱不够，得穿上 TLS 的衣服——而这条路走到头，就是下一章的 Trojan。

本章小结：SS 确立了"密文 + 无特征"的 baseline，也暴露了两个此后十年的主战场——被动统计和主动探测。后面每一代协议，都是在回答这两个问题。

四、Trojan：第一个应对主动探测——真开店（2019）#

4.1 先搞懂：主动探测是什么#

前三代协议面对的海关是被动的——站在路边看你过。主动探测是海关主动敲门：向一台可疑服务器发一个试探包（一个正常的 HTTP 请求、一个伪造的协议握手），看你怎么回应：

  • 回应符合代理协议特征 → 标记，封
  • 干脆不回应 → “一台没有任何服务的服务器却有大流量"也可疑 → 标记，封

SS 的黑箱在这套打法面前很脆弱。如何回应探针，成了新的生死线。

4.2 技术：老老实实跑一个真的 HTTPS 网站#

Trojan 的思路极端而聪明——不发明任何新东西：

  • 服务器上就是一个标准的 HTTPS 服务：真域名、真证书、真网站内容
  • 客户端流量混在正常 HTTPS 里，靠密码哈希认证
  • 任何不带正确密码的连接，全部 fallback 给反代的真实网站——探针发 HTTP 请求，得到的是一个货真价实的网页

形象地说：前几代是"把车伪装成送快递的”，Trojan 是真的开了一家快递公司——海关来查，看到的确实是营业执照齐全、正在营业的店铺。你没有"伪装被识破"的时刻，因为你不是在伪装，你就在正常营业。

4.3 遗留的两个缺口#

  1. 被动伪装缺课（致命）：Trojan 只管外层像 HTTPS，隧道里面怎么装货它完全不管——而这恰恰藏着一个致命的统计指纹（TLS-in-TLS），下一章详述
  2. 证书透明度反查：你买了域名、申请了证书，但这个域名没有历史流量、没有解析记录、没有网站内容——CT 日志里一张"没有店铺的执照”，主动探测者反查时还是可疑

Trojan 解决了"回应探针"的问题，REALITY（第五章）解决"执照"的问题。而中间那个 TLS-in-TLS，是比主动探测更深的一层考题。

五、VLESS + Vision + REALITY：第一个解决被动伪装（2020–2023）#

这三个名字经常连在一起，但它们各占一层、互不冲突：

┌──────────────────────────────────────┐
│ 你的流量（浏览器的 TLS 箱中箱）          │
├──────────────────────────────────────┤
│ VLESS    协议层：UUID 面单，怎么写地址  │
│          + Vision 流控：怎么装车        │
├──────────────────────────────────────┤
│ REALITY  传输层：借真网站的证书做外层TLS │
├──────────────────────────────────────┤
│ TCP / IP                              │
└──────────────────────────────────────┘

5.1 VLESS：极简面单#

先说清 VLESS 是什么。V2Ray 的 VMess（2016）是"带火漆封、密码暗号、还得对表"的老式面单——协议自带一整套加密和协商（还有时间戳校验，时钟不同步就断连），在裸 TCP 年代是必要的自保。VLESS（2020）发现如今所有货都走 TLS 集装箱了，协议层再手写一套密码本纯属脱裤子放屁，于是把面单简化成一张明文密码条：UUID + 目标地址，无加密、无握手、无状态，安全性完全外包给外层 TLS。

VMess（2016） VLESS（2020）
自带加密 有（AEAD 一整套） 无，外包给外层
握手开销 有，多一次往返 无，首包即数据
出过的事故 加密套件有过破解风波 简单到没什么可破

这个"减法"埋了一个漂亮的伏笔：VLESS 不加密 → Xray 能直接看到流经的原始字节 → 才能识别内层是 TLS → 才有下一节的 Vision。当初为减负砍掉的加密，三年后成了 Vision 落地的地基。

5.2 被动伪装的终极考题：TLS-in-TLS#

这是本章的技术核心，值得慢讲——它解释了"为什么外层已经是无懈可击的 TLS，还是会被看出来"。

你用代理访问 https://github.com 时，实际存在两条独立的 TLS 连接：

浏览器 ──内层TLS──> github.com        （你要访问的网站）
   │
   └─> 代理客户端 ══外层TLS隧道══> 代理服务器 ──> github.com
                    （海关只能看到这一段）

内层的全部字节——包括那次握手的每个包——都要从外层隧道里过一遍。关键背景：TLS 加密几乎不改变长度（内容变乱码 + 固定的几十字节开销），所以：

外层密文记录的长度 ≈ 内层明文的长度 + 常数

海关的磅秤于是读出了这套鼓点：

时刻 真实发生的事 海关看到
T1 浏览器发出 ClientHello（约 300–500 字节） 一条约 400B 的密文记录，C→S
T2 github 返回证书链（2–5 KB） 一坨 3–5KB 的密文突发，S→C
T4 下载大文件 16KB 整齐周期的密文（TLS 记录上限 2¹⁴）

判决逻辑：每条 HTTPS 连接的握手都应该明文可见（正常直连时海关直接读到 ClientHello）；这条连接的密文段里却藏着一套统计学上精确复刻"TLS 握手长相"的节奏——该明文出现的鼓点出现在了密文里。不需要解密任何一个字节，只需记录长度、方向、时间做统计分类——成本极低，精度极高。

快递版：你把一个上锁的箱子原封不动塞进另一个上锁的箱子，外层箱子虽然看不到内容，但内箱的棱角把外箱撑出了同样的轮廓——X 光一照，“箱中箱"一目了然。

5.3 Vision：拆箱直发#

病根在"多包一层”，Vision（全名 xtls-rprx-vision，2022）的药方就是"别包"：

  • 识别：Xray 逐连接解析，发现内层流的是 TLS（TLS 记录头是明文结构，类型/长度可读）
  • 握手期：走协议分帧 + 随机填充——握手的长度鼓点太独特，塞泡沫搅乱
  • 数据期：直拷贝——内层箱子本身已上锁（浏览器到 github 的端到端 TLS），代理只把这串密文原样搬进外层连接，不再重复封装。外层 TLS 按自己的 16KB 节奏切分记录，记录边界与内层脱钩，长度镜像消失；附带红利是省掉一整层加解密运算，大流量时 CPU 占用更低

一个容易搞混的点：直拷贝 ≠ 不加密。两个阶段全程都有外层 TLS 加密——ClientHello、UUID、目标地址、HTTP 内容，海关一个都看不到。Vision 消灭的是第二层封装造成的"记录边界一一镜像"这个统计特征，从来不管加锁——锁是外层 TLS 的事，且从未缺岗。（VLESS 严禁裸跑、必须套 TLS，就是这条纪律的反面教材。）

历史插曲：2020 年的初代 XTLS 直切模式是这思路的粗糙版，但模式切换那一刻长度规律会突变，“切换动作本身"成了新指纹被抓过；2022 年的 Vision 是重写版——握手全程填充、过渡无痕。

5.4 REALITY：连执照都是真的#

Trojan 的 fallback 解决了"探针来了给真网页”，但没解决"你的域名没有历史、证书来路可疑"。REALITY（2023）把这条路走到头：

  • 不需要自己的域名和证书。客户端握手时，服务器临时"借用"一个真实知名网站（比如某大公司官网）的证书来完成 TLS 握手
  • 探测者看到的是一次和真网站别无二致的、密码学上无可挑剔的 TLS 会话
  • 探测者去核对：“这家店"确实存在、执照是真的、网站内容也能访问——只是这一切本来就属于别人。CT 日志反查也失效了，因为那张证书本来就有海量正常流量

形象地说：Trojan 是真开了一家店；REALITY 是把你的货车挂靠在沃尔玛名下，用沃尔玛的真执照、真发票跑运输。海关查一万遍，文件全部真实有效。

至此，三件套集齐：VLESS 管面单，Vision 管装车（治被动伪装的箱中箱指纹），REALITY 管外衣（治主动探测）。这是伪装阵营的第一个"全家桶”。

六、Hysteria：搭上 UDP 便车（2022–2023）#

前面所有协议都在 TCP 443 上卷伪装，Hysteria 换了条赛道——它的故事要从一辆"便车"讲起。

6.1 便车从哪来：QUIC 与 HTTP/3#

TCP 改不动了：它在操作系统内核里，升级等于等全世界换系统；更死的是三十年来路上每台防火墙都按老规矩解析 TCP，任何"改良版 TCP 包"会被中间设备当怪物扔掉（协议僵化）。于是谷歌在 UDP 这个"几乎空白的信封"上，把「可靠传输 + TLS 加密 + 多路复用」整套在用户态重写了一遍——这就是 QUIC（用户态意味着随浏览器/App 更新，迭代以周计而不是以年计）。HTTP/3（2022 年标准化）就是跑在 QUIC 上的 HTTP。

QUIC 白送四样东西：握手合并（TCP+TLS 串行 2–3 个 RTT 合成 1-RTT）、流间无队头阻塞（丢包只堵自己那条流）、连接迁移（认 Connection ID 不认 IP，WiFi 切 5G 不断线）、加密默认内置。

连锁反应是：HTTP/3 普及 → UDP 443 成了互联网新命脉 → 海关不敢全网封 UDP → UDP 上突然有了大量"正常车流"可以混。便车来了。

6.2 Hysteria 协议栈：伪装成 HTTP/3 网站#

Hysteria（2022 出第一版，2023 年 Hysteria2 大幅简化）基于 QUIC，核心三件：

你的 TCP 流   → QUIC stream     （流间无队头阻塞，免疫 TCP-in-TCP 追尾）
你的 UDP 流   → QUIC datagram   （明信片原生直通，游戏友好）
伪装外衣      → 长得就是一台 HTTP/3 服务器（443/UDP）

先纠正一个常见误会：Hysteria2 从顶到底没有一粒 TCP。“它伪装成网站"没错，但 HTTP/3 网站本身就跑在 UDP 上——“网站 = TCP"这个等式在 HTTP/3 这代已经作废。伪装成 HTTP/3，恰恰意味着必须是 UDP。

6.3 速度核心：Brutal 拥塞控制#

回顾老病根：传统 TCP 把每次丢包都当堵车，速率砍半再慢慢爬（锯齿形）。跨国线路的丢包十有八九是 QoS 限速或线路噪声，不是真堵车——礼貌协议在白白挨刹。

Brutal 的逻辑：你报一个带宽值 R，就恒定按 R 发；接收端周期回执"实际到手多少”，发端算出真实丢包率 p 后，把发送率提到 R/(1−p)——丢了就多补发，保证到手速率钉死在你报的数上。救护车霸座，烂线路上吞吐碾压一切礼貌协议。

代价也写在名字里：线路真拥塞时它就是流氓，饿死旁边所有排队的车。嫌粗鲁可选 bbr 模式（礼貌版，收益打折）。

6.4 端口跳跃：治 UDP QoS#

UDP 便车的代价是 UDP 会被单独针对（按协议号限速、按端口 QoS）。Hysteria2 的对策：服务端用 iptables 把一整段端口都转进同一个口，客户端定时换着端口发——海关按端口限速，它就打一枪换一个门。

本章定位：Hysteria 代表的路线不跟 TCP 443 上的伪装军备竞赛卷，而是押注 UDP 的未来——HTTP/3 的命脉地位撑起它的生存空间。风险也在此：UDP 被收紧的时段和地区，它最先阵亡，需要回落到 TCP 类协议。

七、AnyTLS：最新的答案（2025）#

7.1 定位：把 Vision 的思路做成协议中立版#

Vision 证明了"治箱中箱指纹"可行，但它绑定 Xray 生态（只配 VLESS）。AnyTLS（2025）用另一套思路独立解了同一道题，作为独立协议进入 sing-box/mihomo 原生支持——不识别、不区分内层是什么，全部流量一视同仁。

7.2 技术：泡沫加混装#

Padding（填充）——往箱中箱的缝隙塞随机泡沫：每帧按可配置策略（如 100–1000 字节随机）附加填充。外层密文块的大小不再贴合内层记录结构——内箱的棱角被泡沫淹没，X 光只能看到一团均匀的噪声。

多路复用（mux）——混装整车，打碎一一对应：多条代理流共用一条 TLS 连接。传统 Trojan 是"一单一车”，装载序列就是单个客户内箱的镜像；AnyTLS 把几十个客户的箱子交错混装进同一辆卡车，海关看到的装载序列是所有客户流量的模糊叠加——想在合唱里单独听出一个人的呼吸，统计上不可能。

附带红利：客户端预建若干空闲会话（min_idle_session），新请求直接装车、免握手，首包延迟显著更低——开网页的爽感主要来自这里（代价是要靠定时心跳维持空闲连接，防止 NAT 网关把久未使用的映射悄悄掐掉）。

7.3 与 Vision 一句话对比#

Vision 消除特征（识别内层是 TLS，数据期不再制造第二层结构），AnyTLS 淹没特征（不识别，全部加噪声）。一个做减法、一个加噪声，殊途同归——完整的横向对比见第九章。

7.4 局限#

  • 只跑 TCP（UDP 靠 UDP-over-TCP 承载）：继承了 TCP 在高丢包线路上的队头阻塞——它优先隐蔽，不优先速度，烂线路请找 Hysteria2
  • mux 的结构性代价：几十条流挤一根 TCP 管道，丢一个包全体排队——开网页爽、大下载未必赢
  • 需要真域名 + 真证书（这点不如 REALITY 省事）

八、插曲：提速的三个战场#

五大协议讲完了，把散落各章的提速知识收拢一下——因为"快"其实是三种不同的快感，病根和药方各不相同。

8.1 病根诊断#

病根 机理 快递版
高 RTT 吞吐上限 = 窗口 ÷ RTT；旧 TCP 窗口 64KB × 200ms ≈ 2.6Mbps 封顶 车队规模有限，路越长运力越低
丢包 × TCP 礼貌 一丢包速率砍半慢慢爬回；1% 丢包 + 200ms RTT 下千兆线路只剩不到 1Mbps 司机一遇颠簸刹车减半，十公里颠一下全程爬行
协议开销 用户态拷贝、双重加解密、逐连接握手 每件货人工搬进搬出仓库；每车重办全套手续

8.2 延迟战：少问几句#

N-RTT 数的是"握手要跑几个来回"——数据最早能搭上第几波，就决定总耗时几个 RTT。TLS 1.2 是四波（2 RTT）且砍不动：钥匙必须用证书公钥锁着送（没证书交不了）、Finished 必须用新密钥加密验锁（没钥匙验不了），因果链是串行的。TLS 1.3 砍到 1-RTT 的办法是赌：套件精简后客户端第一波就把密钥材料押上，服务器一收一发双方密钥即齐，数据搭第二波出发。

总账单（打开网页到首字节，跨国 200ms/圈）：

方案 握手圈数 请求 合计 耗时
TCP + TLS 1.2 1+2 1 4 RTT ~800ms
TCP + TLS 1.3 1+1 1 3 RTT ~600ms
QUIC（传输+加密合并握手） 1 1 2 RTT ~400ms
QUIC 0-RTT 0 1 1 RTT ~200ms

两个易混的技术再辨一次：0-RTT 会话恢复保管的是票根（上次连接发的密钥材料记忆），连接本身仍要新建，第一波捎上数据；mux 预热连接（AnyTLS）保管的是现役车辆——连接活着、密钥热着、拥塞窗口不冷启动，压根不存在"新建"这个动作。一个是"重办手续不用排队"，一个是"手续根本不用办"。两者分层可叠加：mux 负责尽量不重连，0-RTT 负责真要重连时也快。（0-RTT 的代价：early data 可被重放，严格实现只对幂等请求放行。）

8.3 吞吐战：一次多装点#

技术 出处 干了什么
内核态运行 WireGuard、IPsec 传送带直连，不再人工搬运
直拷贝 XTLS Vision 数据期省掉一整层加解密
BBR Google 摸清路况定巡航速度，丢包当噪声，不再见颠簸就刹车
Brutal Hysteria2 按报的带宽硬发，丢了就补发（详见第六章）

8.4 物理战：算法治不了的病#

协议再快也快不过烂路由。跨国默认路由常绕地球一圈，于是有了中转架构（家→国内中转机→境外落地，入境段走 CN2/9929 优化线路）和专线 IPLC/IEPL（不过海关的专属货运铁路，按 Mbps 卖、贵）。游戏加速器（UU、雷神）就是物理战的产品化：专线 + 机房旁出口 + 只运游戏流量，把 200ms 押到 30–80ms 靠的不是协议魔法，是花钱买路。

实战经验：线路档次对速度的影响通常大于协议选择——WireGuard 走垃圾线路照样输给 Trojan 走 IPLC。

九、五家对比：协议与背后的技术#

9.1 协议总表#

9.2 加密：所有人的答案都一样#

先看一个反直觉的事实——线路密文从来不是这些协议自己提供的：

协议 线路加密由谁保证
SS 自带 AEAD（例外：它诞生时默认裸 TCP）
Trojan / VLESS / AnyTLS 外层 TLS
Hysteria2 QUIC 内置 TLS

TLS 成熟之后，“加密"这门主课就全班交卷了，协议层的全部精力转向后两件事。这也解释了 VLESS 敢做成明文面单、Vision 数据期敢直拷贝——锁一直是外层的，从没缺过岗。

9.4 被动伪装：Trojan / Vision / AnyTLS 逐阶段对照#

被动伪装的核心考题只有一个——TLS-in-TLS 指纹。三家答卷：

阶段 线路密文由谁保证 Trojan Vision AnyTLS
握手期 外层 TLS（从未缺岗） 无处理【死穴】 +随机填充 +随机填充
数据期 外层 TLS（同样在岗） 无处理 直拷贝，零干预 继续逐帧填充
连接模型 —— 一流一连接 一流一连接 多流复用 + 预热
Trojan Vision AnyTLS
海关磅秤看到 密文段里一段"第二次握手"的鼓点 → 教科书 TLS-in-TLS 填充噪声 → 16KB 均匀流，与正常 HTTPS 下载无法区分 任意时刻都是多流交错的随机大小帧，单流特征被淹没
带宽/CPU 开销 无 数据期几乎为零 每帧都付填充税
首包延迟 每条新流新建连接 同左 mux 预热，新流秒上车【优势】
丢包行为 各流独立 各流独立 一条管道多流复用，队头阻塞

三种哲学收口：Trojan 原样搬运，赌海关不细看；Vision 是外科医生，先看内箱是什么再决定动不动刀（数据期零开销，但绑定 Xray 生态）；AnyTLS 是粉碎机，不管什么箱全部拆成随机包裹塞泡沫混装（任何流量一律有效，代价是全程付填充税）。

9.5 TCP 路线 vs UDP 路线#

最后一条分野是赛道选择：

  • TCP 443 路线（Trojan/VLESS/AnyTLS）：命脉端口哪都不封，生存能力最强；代价是 TCP 的礼貌（丢包减速）和 mux 的队头阻塞
  • UDP/QUIC 路线（Hysteria2）：握手快、流间无阻塞、拥塞控制自主（Brutal/bbr 随便换）；代价是 UDP 可被单独针对，命脉地位依附于 HTTP/3 的普及进程

没有赢家，只有取舍——这也是为什么成熟的翻墙客户端都支持多协议自动切换。

十、总结：三十年在争什么#

三代矛盾的接力#

阶段 年代 主要矛盾 谁解决了它
第一阶段：锁不够结实 1999–2005 加密被破解、认证被伪造 L2TP/IPsec、OpenVPN、IKEv2
第二阶段：车不够快 2005–2020 性能瓶颈、握手慢、配置地狱 IKEv2、WireGuard、QUIC
第三阶段：长得像 VPN 2012–至今 被动统计 + 主动探测 SS → Trojan → Vision/REALITY → AnyTLS

选型决策树#

你的需求是什么？
│
├── 纯隐私/自建内网穿透，不怕被识别
│   └── WireGuard（最简单、最快、最省心）
│
├── 过海关 + 追求极致伪装和性能
│   └── VLESS + Vision + REALITY
│
├── 过海关 + 客户端在 sing-box/mihomo 生态 + 要低延迟开网页
│   └── AnyTLS（mux 预热连接的首包优势）
│
├── 烂线路抢带宽，且 UDP 可用
│   └── Hysteria2（UDP 被限时回落 TCP 类协议）
│
└── 打游戏（要 UDP 直通与低抖动）
    ├── 自建 → WireGuard 或 Hysteria2，节点开启 UDP 转发
    └── 国内联机卡 → 游戏加速器（买的是线路，不是协议）

三十年的故事讲完了。每一代的"解决"都精确地成了下一代的"问题”：锁结实了才发现车慢，车快了才发现长得像 VPN，长得不像 VPN 了才发现箱中箱的轮廓，箱中箱治好了又开始押注 UDP 的未来。这场军备竞赛没有终局——海关的磅秤和协议设计师的泡沫，都还在进化。
